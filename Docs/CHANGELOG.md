## 2026-10-10 — [Downloader False-Success Fix]

- **`download_models.sh` reported "Model Download Complete!" even when downloads failed**: `download_ardy()` swallowed the gated-repository failure (warnings only, implicit `return 0`), and the main loop ignored every `download_*` return code before printing the success banner. ARDY (gated `nv-tlabs/ardy`, Meta-Llama access) and TripoSG's RMBG-1.4/TripoSG components had the same swallow pattern. Failures now `print_error` + `return 1` with actionable guidance (request gated access, `export HF_TOKEN=...`), the loop tracks failures, and the script exits 1 with an error summary instead of a false SUCCESS banner. Verified: gated ARDY run exits 1 with the real HF error; already-verified model run exits 0 with the banner. TripoSG-scribble remains intentionally optional (`|| true`).

## 2026-10-10 — [Mesh-Tool File References: file_id Plumbing & URL Input Resolution]

- **Mesh tools (remesh/texture/UV/segment/edit) failed with "Server file path is outside configured input roots"**: the workspace read `currentAsset.source.fileId`, which was never populated anywhere, so the supported `mesh_file_id` branch was dead code and every request fell back to sending the asset's browser URL in `mesh_path`, which `resolve_server_file_path` rejects by design. Generated/imported meshes now carry a real backend file reference: `normalizeModelAsset` preserves `fileId` on the asset and its `source`, job-derived assets expose `job-{job_id}` (registered in the file store by `GET /system/jobs/{job_id}`), and all five mesh-tool call sites send `mesh_file_id` — falling back to `mesh_path` only for genuine local paths, otherwise failing with a clear client-side message instead of a backend 500.
- **Backend URL-input resolution**: new shared `resolve_input_reference_async` (`backend/api/routers/file_upload.py`) resolves `/api/v1/file-upload/download/{file_id}` URLs, `/api/v1/system/jobs/{job_id}/download` URLs, and bare `/{uuid}` paths through the file store (identifier, then `job-{identifier}`) with the existing disk-glob fallback; wired into `mesh_retopology`, `mesh_uv_unwrapping`, `mesh_segmentation`, `auto_rigging`, and the shared `process_file_input` helper in `mesh_generation` (texture painting/editing inputs). Local-path security checks are unchanged.
