# Mesh Generation

Open **Workspace → Model** at `/workspace/generate`. Choose an available image-to-3D model, provide the reference image, and review the output controls before submitting.

## What the main controls do

- **Model** chooses the registered image-to-3D model. Readiness depends on the backend and installed model weights.
- **Seed** is a request input used by the adapter and candidate planner. The numerical inference profile itself belongs to the model adapter.
- **Candidate Variations** requests multiple candidates; the planner, configured cap and available runtime resources determine how many are actually executed.
- **Target Poly Count** is a downstream production budget. It does not change the model's native inference resolution or sampling profile. Native/Raw output bypasses the production decimation budget.
- **Topology, texture atlas, LOD, QA/repair, auto-rig and collision** are post-processing choices. They depend on the selected options and on the associated backend/runtime components being available.

## After submission

Watch the job status and stage messages. A requested post-processing step is not proof that it completed: inspect the final production status, warnings and generated artifacts. GPU inference and optional stages can fail independently, and a degraded output should be treated as needing review.
